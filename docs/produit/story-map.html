Luniqo · User Story Map

Version 2 · carte conçue par Thomas Abadie, d'après la méthode de Jeff Patton · personas : PERSONAS.md (4 personnalisés + 2 imposés par le TD) · tickets : Jira, projet LUN · version lisible sur GitHub : STORY-MAP.md

Objectif du MVP (v1.0.0) : une micro-crèche remplace ses fiches papier de présence et de ménage, et les parents voient la journée de leur enfant, sans aucune donnée de santé.

De gauche à droite : l'ordre du récit (de l'installation de la crèche au suivi par les parents). De haut en bas : la priorité. Chaque ligne horizontale découpe une version ; tout ce qui est au-dessus de la ligne MVP suffit pour qu'une première crèche utilise Luniqo pour de vrai.

Ce qui change par rapport à la V1

V1V2
Un tableau Markdown : activités, tâches et stories mélangées dans la même cellule.Trois niveaux distincts, comme le modèle du cours : activités (épics) → étapes (US) → détails (sous-tâches).
Activités inventées pour la carte, sans lien direct avec Jira.Les activités sont les épics Jira, rangés dans l'ordre du récit ; chaque colonne est une US.
Détails écrits comme des tickets techniques ([Front], [Back]).Détails écrits du point de vue de l'utilisateur ; le ticket reste noté sur le post-it.
4 personas.6 personas : Alex et Margeritte, imposés par le TD, ajoutés ; leurs besoins sont marqués 🕹️ et 🖥️ sur la carte.
Chaque version n'a qu'un nom.Chaque version a un objectif et des critères de réussite.
Un seul repère d'avancement (✅ = API faite), posé à tort sur la fiche de ménage, qui n'avait alors pas d'API.Trois repères tirés de Jira et du code : API, écrans, tickets faits. Depuis, l'API du ménage existe (LUN-100, LUN-102, LUN-104) : le badge API est revenu, il manque les écrans.
Socle technique dans la carte des utilisateurs.Socle sorti de la carte, dans une bande de fondations, avec la gestion des erreurs imposée par le TD.
